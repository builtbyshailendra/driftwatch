# ADR 0001: Read the JSON plan, not the human plan output

- Status: accepted
- Date: 2026-11-07
- Deciders: Shailendra Singh

## Context

A drift detector needs to know which resources Terraform would change, how,
and why. There are three places to get that from:

1. The human-readable output of `terraform plan`.
2. The exit code of `terraform plan -detailed-exitcode` alone.
3. The machine-readable plan from `terraform show -json <planfile>`.

The human output changes between Terraform releases, colours and wraps text,
and prints sensitive values as `(sensitive value)` with no way to tell which
attribute paths were masked. The exit code says only that something changes.

## Decision

driftwatch always works from the JSON plan (format version 1.x). When asked to
run Terraform it saves the plan with `-out` to a temporary file, converts it
with `terraform show -json`, and deletes the file. It also accepts a saved plan
file or ready-made JSON, so pipelines that already run `terraform plan` do not
plan twice.

It uses `-detailed-exitcode` only to tell "plan succeeded" (0 or 2) from
"plan failed" (1); the drift decision comes from the JSON.

The project has no third-party Go dependencies. The ignore file uses a small
line format instead of YAML, and the GitHub and Slack clients are a few
hundred lines over `net/http`.

## Consequences

- Classification uses the documented `actions`, `action_reason`,
  `replace_paths` and `resource_drift` fields, which Terraform keeps stable
  within format 1.x. driftwatch refuses other major versions instead of
  guessing.
- Sensitivity is handled per attribute from `before_sensitive` and
  `after_sensitive`. The JSON plan contains the plaintext values, so masking
  happens in the analysis step before anything is rendered, and the temporary
  plan file is deleted as soon as it has been converted.
- Tests run against real plan JSON committed under `testdata/plans`,
  generated by `scripts/gen-fixtures.sh` from a workspace that uses only the
  null, random and local providers. No cloud account is needed to reproduce
  them.
- Without dependencies there is nothing to audit or update beyond the Go
  toolchain, at the cost of writing a little more code for HTTP and parsing.
- driftwatch does not interpret provider schemas. If a provider fails to mark
  an attribute sensitive, driftwatch shows it, exactly as `terraform plan`
  would.
